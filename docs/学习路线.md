# 如何学习心之林

先用自己的练习数据学习，避免直接改动正在使用的记录。浏览器的不同地址或不同应用配置目录有独立存储；不要把本机测试指向真实同步仓库。

## 第一阶段：跑起来，看见变化

运行 `python tools/build.py --web`，在 `web/dist` 启动本地服务，再导入 `examples/练习生活图.json`。依次体验层级展开、查看详情、加入今天、打勾、刷新后保留状态和图谱切换。

接着阅读 `work/life/tree.js` 与 `tree.css`。找出创建列表、递归遍历子节点、点击事件和视图切换的位置。小练习：调整行间距，重新构建并观察；然后恢复。不要直接修改生成的 `web/dist/app.js`，下次构建会覆盖它。

这一阶段要能回答：为什么收起分支不会删掉节点？为什么切换图谱也不会复制一份数据？

## 第二阶段：理解数据，不急着看全部页面

阅读 `work/life/model.js` 和 `model-check.cjs`。关注 `index`、`children`、`ancestors`、`path`、`progress` 等函数。节点的 `parents` 表示结构路径；同一个节点可以有多个上层路径。记录通过 ID 关联，不依赖界面位置。

运行 `node work/life/model-check.cjs`。小练习：用一份小对象手动添加两个愿望和一个共同子节点，打印它的上层路径。再故意形成回环，观察校验拒绝它。

这一阶段要能回答：树形阅读界面和底层允许多路径的数据结构为什么可以共存？

## 第三阶段：追踪一次完整操作

从 `tree.js` 中 `data-tree-today` 的点击开始，顺着 `simpleSchedule` 找到 `work/life/simple.js`，再到 `base.html` 中 `scheduleAction`、`renderToday`、`undoCompletion` 等实现（用编辑器搜索函数名）。

画出这条链：节点 ID → `placements` 中当天安排 → 完成产生 `logs` → 可补充 `evidence` → 保存 → 重新渲染。

运行 `python tools/check.py`。小练习：写下“加入今天”和“已经做过”为什么不是同一个状态；找到取消完成如何避免留下重复待补结果的处理。

## 第四阶段：理解导入和关联

阅读 `work/life/network-import.js`，再阅读 `tools/network-check.cjs`。先看如何校验节点、拆解边与层级，再看如何生成稳定编号、追加导入和跳过重复。

小练习：复制练习 JSON，增加一个合法的末端行动，然后导入两次，验证不会出现重复节点。注意 `decomposes` 与 `supports` / `enables` 的区别：后两种是关联，不应让行动失去末端资格。

## 第五阶段：最后再学同步

先阅读 `work/sync/core.js` 里的标准数据和三方合并，再看 `engine.js` 的保存、拉取、合并、重试及冲突流程。运行：

```sh
node work/sync/core-check.cjs
node work/sync/engine-check.cjs
```

这些测试使用内存中的模拟远程服务，不需要连接密钥。小练习：跟踪“两端各添加一件事”和“两端修改同一个标题”的结果有什么不同。

随后阅读 `web/vault.js`（IndexedDB、附件与重新连接）、`web/github.js`（远程接口适配）。理解“数据规则”和“设备存储/网络调用”如何分开。

## 第六阶段：看懂各端外壳

阅读 `work/android/src/app/mindgarden/personal/MainActivity.java`、`work/windows/App.cs`，再看各自的存储与 GitHub 适配。它们承载同一份网页功能，通过桥接提供原生文件、备份和网络能力，不是三个完全独立的产品。

原生打包需要额外工具。先能独立构建网页、通过核心检查，再按[构建说明](构建与检查.md)准备环境。不要把原作者的安卓签名私钥当作学习所需文件。

## 读代码遇到困难时

每次只问一个具体问题，例如“点加入今天后，哪一个数组变了”“为什么跨分支连线不算父子关系”。先查找入口函数、数据读写、保存点和渲染点，沿调用链阅读。这个项目保留了早期页面和后续覆盖函数，不能仅凭文件前部某个同名函数就判断最终行为，要继续查找后面的赋值或覆盖。

适合后续学习的改善包括：补充有意义的边界测试、统一版本号、减少字符串拼接构建、逐步拆开基础页面中的数据与界面逻辑。每次只做一项，保留当前数据兼容性，不要一开始就重写所有模块。
